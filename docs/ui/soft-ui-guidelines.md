# Fulcrum · Soft UI 视觉与交互规约

版本：2026-11-14。适用于企业工作台、平台后台、登录注册和公开站点。

本文是本轮实现和验收的唯一视觉标准。历史 Scandinavian / Swiss 文档仅记录历史决策，不再指导新页面。页面进度见同目录 `soft-ui-page-checklist.md`。

## 1. 参考目标的调性

来源：`https://www.stylekit.top/zh/styles/soft-ui`。已读取页面的 Hard Prompt、Design Spec、交互规则及自检清单。

提炼为四个特征：

1. **柔和有层次**：浅灰环境、白色表面、靛紫强调；通过有模糊半径的轻阴影和圆角区分内容。
2. **轻盈而清楚**：标题使用深灰，正文与辅助信息依次减弱；避免用低对比文字营造“高级感”。
3. **有触感的操作**：可点击元素有轻浮起、按压和柔光焦点；表格与图表保持稳定。
4. **一致的秩序**：同一语义只对应一套组件样式；公开站点和后台可以有不同密度，但不能像不同产品。

高级感的验收依据是比例、对齐、层次、排版与状态完整性。大面积空白、大色块、强阴影、玻璃模糊和装饰线不作为质量指标。

## 2. 将参考适配为商业后台

参考主要面向消费类界面，推荐宽松卡片间距与大段落留白。用户明确要求紧凑后台，本项目作如下有意适配：

| 维度 | 本项目规则 | 原因 |
| --- | --- | --- |
| 调性 | 保留柔和色彩、圆角、柔影、轻交互 | 保持参考识别度 |
| 后台密度 | 16–20px 区块间距、18–20px 内边距 | 主内容进入首屏 |
| 数据布局 | 列表优先、指标紧凑、图表高度稳定 | 便于比较和连续阅读 |
| 后台宽度 | 最大 1600px，桌面两侧各 24px | 减少宽屏空白 |
| 登录 | 单一双栏表面，品牌信息精简 | 清晰聚焦登录动作 |
| 公共页 | 64px 左右区块留白 | 保持产品介绍节奏 |
| 动效 | 数据表面静止，操作控件轻反馈 | 避免阅读时抖动 |
| 移动触控 | 交互目标至少 44px | 紧凑不等于难操作 |

优先级：用户明确需求 > 本项目规约 > 参考通用提示词。不得用参考的宽松间距反向恢复后台大留白。

## 3. 色彩与材质

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#f5f6fa` | 全站浅灰环境 |
| `--surface` | `#ffffff` | 主业务表面 |
| `--surface-soft` | `#f8fafc` | 输入框、表头、悬停行 |
| `--surface-muted` | `#f1f5f9` | 中性控件与次级背景 |
| `--text` | `#1f2937` | 标题、关键数值 |
| `--text-soft` | `#475569` | 正文 |
| `--muted` | `#64748b` | 辅助信息 |
| `--primary` | `#6366f1` | 品牌、焦点、图形 |
| `--primary-strong` | `#5154c9` | 白字主按钮、操作链接 |
| `--primary-soft` | `#eeefff` | 选中态、品牌浅底 |
| `--border` | `#e8ecf3` | 必要的行分隔与控件边界 |
| `--border-strong` | `#cdd5e4` | 控件悬停，不能当主分区线 |
| `--success` / soft | `#18745e` / `#e8f6ef` | 在线、正常 |
| `--info` / soft | `#496ba8` / `#edf2fc` | 信息、次级数据 |
| `--warning` / soft | `#a66416` / `#fff5df` | 待处理、需要关注 |
| `--danger` / soft | `#bd4260` / `#fdf0f3` | 失败、危险操作 |

品牌浅色不能直接作小字号文字；按钮使用加深主色保证白字可读。图表可以使用靛紫、蓝灰、青绿和赭黄，但图例必须有文字，不能只靠颜色解释。

- 主圆角：业务卡片 20px，认证外框 24px，输入框和按钮 16px，紧凑控件 10px。
- 圆形用于头像、渠道图标和状态点；徽标可使用胶囊形。
- 卡片阴影：`0 4px 20px rgba(72,82,140,.055), 0 1px 3px rgba(72,82,140,.025)`。
- 浮层阴影：`0 16px 44px rgba(72,82,140,.12)`。
- 聚焦光环：`0 0 0 4px rgba(99,102,241,.16)`，同时保留明确的 focus-visible。
- 表格内行、卡片内信息区、代码区不叠加第二层悬浮卡片。

## 4. 字体与排版

继续使用项目自托管的 Albert Sans / Noto Sans SC，不引入远程字体。中文常规字重 400，标题 600–650，数字使用等宽数字特性。

| 层级 | 桌面 | 手机 | 规则 |
| --- | --- | --- | --- |
| 后台页标题 | 26px | 24px | 一页一个 h1，与主要操作同行 |
| 区块标题 | 18px | 17–18px | 简短业务名称 |
| 关键指标 | 30px | 26px | 数字和单位分层，长时间值不放大 |
| 后台正文 | 14px / 1.6 | 14–15px / 1.6 | 不靠缩小正文压缩布局 |
| 表格、表单标签 | 13px | 13–14px | 字段始终有可见标签 |
| 辅助信息 | 12px | 12px | 不承担唯一操作指引 |
| 登录标题 | 30px | 26px | 主动作明确，少解释文案 |
| 登录品牌标题 | 32px | 隐藏非必要长标题 | 不挤占手机输入区域 |
| 营销主标题 | 64px | 44–48px | 不影响行动按钮可见性 |

删除后台标题上重复的英文 kicker 和“平台运营 / 企业运营”眉题。身份由顶部品牌区说明，区块由中文标题说明。长文本正常换行，不能用固定高度裁切。

## 5. 空间与布局

- 间距刻度：4 / 6 / 8 / 12 / 16 / 20 / 24 / 32 / 48 / 64px。
- 后台顶部栏 64px；内容顶部 24px；页面标题到底部内容 20px。
- 主内容最多 1600px；公开站点最多 1200px；认证框约 1040px。
- 后台双列表面间距 16px，独立区块间距 20px；卡片内部 20px。
- 表单字段之间 14–16px；label 到 input 6px。一个字段使用一个网格单元。
- 数据表行内边距 11px 12px；管理清单常规行高 66px，内容增加时自动撑开。
- 图表约 210px 高；空状态保留简洁文字和相邻行动，不撑成巨大空卡片。
- 指标网格使用独立、等高、低阴影表面；同组双列卡片由 CSS Grid 拉伸对齐，不写死内容高度。
- 不通过把筛选条件、重复说明和装饰内容移成大卡片增加页面长度。

## 6. 共享组件规则

### 导航与页面标题

保留顶部菜单。当前一级入口用浅靛背景与加深文字，二级菜单自然换行，不生成横向滚动条。平台菜单仍包含租户、套餐、订单、员工与运维；企业菜单不出现平台操作。主要操作与标题靠近，避免空行。

### 按钮、状态与通知

主要按钮为加深靛紫；次级按钮白底低对比边界；危险操作玫红并保留原确认流程。桌面按钮 40px，筛选 36px，触控至少 44px。通知使用浅色完整表面，不使用单侧粗色条；错误文本必须可读并在认证表单旁呈现。

按钮状态必须包含默认、hover、active、focus-visible、disabled。hover 最多上移 2px，active 回位并轻微缩放；不能让布局重新排版。禁用状态不浮起。

### 表单

浅灰输入底、圆角、低对比边界，focus 显示柔光且背景转白。标签与字段成组。占位文字仅作示例。保持现有 name、action、CSRF、自动填充和校验属性。密码可见切换使用原生按钮，有可访问名称和 aria-pressed，默认隐藏密码。

### 筛选、表格、管理清单

筛选放在结果表面顶部；桌面单行优先，字段多时自然换行。手机折叠，已生效条件可见。数字对齐，状态带文字；表格只在局部容器横向滚动。员工、租户、套餐等继续使用清单及编辑弹窗，不能退回大块逐项表单。

员工与套餐的新增表单也按需在弹窗中打开。插件目录与平台插件管理使用统一的功能卡片：桌面三列、平板两列、手机一列，直接展示名称、版本和完整功能介绍；企业页底部展示开发者与配置入口，必要的异常与警告保持可见。图表改为单一趋势曲线时，逐小时精确读数须保留在可键盘展开的明细中，不能以精简界面为由删除数据。

### 弹窗与业务详情

白底圆角、柔影、有限高度，内部滚动，关闭按钮可达。详情页使用信息分组与局部浅底，不嵌套多个悬浮卡片。二维码和付款码保持原始比例与白底，不改变内容和扫码链路。

弹窗关闭后返回可见的触发元素：页头新增按钮或记录行菜单摘要，不能把焦点还给已收起菜单内的隐藏按钮。网格内的小节必须允许收缩，不能由内部表格的最小宽度撑开整页。

## 7. 认证页面

- 企业登录、平台登录、注册共用视觉壳，账号体系与请求路径仍各自独立。
- 页顶品牌和“返回首页”；主框左侧品牌说明与原生渠道示意，右侧单一表单；底部仅简短品牌语。
- 品牌示意只表示微信、企业微信、Telegram 等渠道汇聚，不伪造业务数字、客户口碑或运行状态。
- 企业登录：手机号、密码、登录按钮、注册链接；不出现租户编码。
- 平台登录：用户名、密码、平台登录按钮、企业入口提示；不展示企业注册表单。
- 注册：企业名称/联系人、手机号、密码/确认密码、验证码、提交；标签和输入不得分成独立网格行。
- 通知固定在右侧表单列，错误不得使表单挤到下一列或消失。
- 手机压缩品牌说明并隐藏示意图，登录按钮在 390×844 首屏内可达；注册允许自然纵向滚动。

## 8. 响应式与可访问性

- 1440×900：评估正常后台密度；1024×768：检查导航和数据网格；390×844：检查输入、菜单、表格和弹窗。
- 820px 以下主导航折叠，双列表面转单列，认证表单优先。
- 560px 以下关键指标保持两列，标签较长或内容型统计允许单列。
- 页面根节点 `scrollWidth <= clientWidth + 1`；仅表格、日志或代码允许局部滚动。
- 保留 skip link、单一 h1、字段 label、键盘焦点、图片替代文本与通知播报。
- 非装饰文本对比度目标至少 4.5:1；不得把白字放在浅靛背景。
- 尊重 prefers-reduced-motion，减少动态时取消上浮和示意图位移。
- 不新增图表框架、UI 框架、远程字体或装饰性大图依赖。

## 9. 明确禁止

1. 恢复红色大面积主背景、黑色硬边、4px 标题规则和直角主表面。
2. 后台沿用 42px 大标题、48px 区块间距和 1280px 窄内容上限。
3. 每个区块重复英文眉题、研发过程解释或技术栈说明。
4. 增加旧样式别名、主题开关、双份导航、CSS 文件末尾永久补丁层。
5. 把浏览器预览数据宣称为生产数据，把截图检查宣称为完整回归。

## 10. 页面完成标准

每页按“结构 → 风格 → 密度 → 状态 → 响应式”顺序检查，再在清单登记证据。

1. 信息顺序与业务主动作明确，保留有效功能。
2. 页面使用本规约 token，无旧 Swiss 专属样式。
3. 桌面列表的主要结果开始位置目标在首屏上半部；大盘趋势图在 KPI 后紧邻出现。
4. 验证正常、空数据、错误或弹窗等与本页相关的关键状态。
5. 完成对应轻量模板/接口检查；代表页完成浏览器桌面与手机检查。
6. “共享样式覆盖”“模板检查通过”“浏览器实测通过”分别记录，不将一种证据替代另一种。
